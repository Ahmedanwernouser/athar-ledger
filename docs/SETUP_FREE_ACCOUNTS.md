# الإعداد المجاني — خطوة بخطوة (≈ ٣٠ دقيقة، بلا بطاقة دفع)

> **قاعدة ذهبية:** لا تلصق أي مفتاح API في الشات، ولا في أي ملف داخل المستودع، ولا في سطر أمر يُحفظ في سجلّ الطرفية. المفتاح يُكتب مرة واحدة فقط حين يطلبه منك الأمر `wrangler secret put` (الخطوة ٤-د).

## ١) GitHub (مستودع عام)
1. أنشئ مستودعًا **Public** باسم `athar-ledger` (بلا README تلقائي).
2. ارفع محتويات هذا المجلد (ما عدا `data/raw/` — مستثنى في `.gitignore`).
3. أنشئ الوسم: `git tag baseline-v0 && git push origin baseline-v0` وسجّل الـ hash في `BASELINE.md`.

## ٢) Cloudflare Pages (الواجهة) — قبل الـ Worker
1. Cloudflare Dashboard ← Workers & Pages ← Create ← Pages ← Connect to Git ← اختر المستودع.
2. Build command: *(اتركه فارغًا)* · Build output directory: `public`.
3. بعد النشر ستحصل على عنوان مثل `https://athar-ledger.pages.dev`. **انسخه كما هو بالحرف** (يبدأ بـ `https://` وبلا شرطة مائلة `/` في آخره): هذا هو «الأصل» (origin) الذي سنسمح له في الخطوة ٤-ج.

## ٣) Groq (التفريغ الصوتي) — مختلف عن Grok
1. console.groq.com ← API Keys ← Create. (Groq = شركة الاستدلال السريع؛ Grok = نموذج xAI. للتفريغ نحتاج Groq.)
2. انسخ المفتاح إلى الحافظة فقط؛ ستلصقه في الخطوة ٤-د ثم لا تحتاجه بعد ذلك. لا تحفظه في ملف.
3. **لا تُضِف بطاقة دفع إلى حساب Groq** (ولا إلى حساب Google إن استخدمت Gemini). بلا بطاقة، أسوأ ما يحدث عند انتهاء الحصة المجانية هو توقّف الخدمة حتى اليوم التالي.

## ٤) Cloudflare Worker (يُخفي المفتاح ويحمي الحصة المجانية)

طريق واحد فقط: **سطر الأوامر بأداة `wrangler`**. لا تعدّل إعدادات الـ Worker من لوحة Cloudflare: كل نشر جديد يكتب فوقها ما في الملف `worker/wrangler.toml`، فالملف هو المرجع الوحيد.

تحتاج: [Node.js](https://nodejs.org) مثبَّتًا على جهازك (النسخة 20 أو أحدث)، وطرفية (Terminal في ماك/لينكس، أو PowerShell في ويندوز).

### ٤-أ) ادخل المجلد وسجّل الدخول
```bash
cd worker
npx wrangler login
```
سيفتح المتصفح صفحة Cloudflare: اضغط Allow. (أول مرة سيسألك `npx` هل ينزّل `wrangler`: أجب `y`.)

### ٤-ب) أنشئ مخزن العدّادات (إجباري)
```bash
npx wrangler kv namespace create CAP
```
سيطبع الأمر سطرًا فيه `id = "…"` (حروف وأرقام طولها ٣٢). افتح `worker/wrangler.toml` وضع هذا الـ id مكان `REPLACE_WITH_KV_NAMESPACE_ID`:
```toml
[[kv_namespaces]]
binding = "CAP"
id = "ضع الـ id هنا"
```
هذا المخزن هو الذي يعدّ الطلبات. **بدونه يرفض الـ Worker العمل عمدًا** (يردّ بـ `server_not_configured`)، حتى لا تعمل الخدمة يومًا بلا حدود دون أن تدري.

### ٤-ج) حدّد المواقع المسموح لها
في `worker/wrangler.toml` غيّر السطر:
```toml
ALLOWED_ORIGINS = "https://REPLACE-WITH-YOUR-PROJECT.pages.dev"
```
إلى عنوان موقعك الذي نسخته في الخطوة ٢، مثلًا `"https://athar-ledger.pages.dev"`. انتبه:
- المطابقة **حرفية**: `https://` في الأول، وبلا `/` في الآخر، وبلا مسافات.
- عناوين المعاينة في Pages (مثل `https://a1b2c3d4.athar-ledger.pages.dev`) والنطاق الخاص (مثل `https://athar.example.com`) **أصول مختلفة**. إن أردت أن يعمل التفريغ منها فأضفها مفصولة بفاصلة: `"https://athar-ledger.pages.dev,https://athar.example.com"`.
- `http://localhost:8788` يُضاف **فقط** وأنت تجرّب الموقع على جهازك (`npm run serve`)، ثم احذفه وأعد النشر.
- لا تكتب `*` أبدًا (لن يعمل أصلًا: الـ Worker يتجاهله).

### ٤-د) ضع مفتاح Groq سرًّا
```bash
npx wrangler secret put GROQ_API_KEY
```
سيظهر لك سطر يطلب القيمة: الصق المفتاح هناك واضغط Enter (لن يظهر على الشاشة). إن سألك wrangler هل ينشئ Worker جديدًا باسم `athar-asr` فأجب `y`.

هكذا لا يُكتب المفتاح في أي ملف، ولا في الشات، ولا في سجلّ أوامر الطرفية. **لا تكتبه هكذا أبدًا:** `GROQ_API_KEY=gsk_... أمر` — فهذا يحفظه في سجلّ الأوامر.

### ٤-هـ) انشر
```bash
npx wrangler deploy
```
سيطبع عنوان الـ Worker، مثل `https://athar-asr.<حسابك>.workers.dev`. انسخه.
إن فشل النشر برسالة عن KV namespace فأنت لم تضع الـ id في الخطوة ٤-ب.

### ٤-و) اختبر (أربعة اختبارات، دقيقتان)
في الأوامر التالية ضع عنوان الـ Worker مكان `WORKER` وعنوان موقعك مكان `SITE`، واجعل `clip.m4a` أي مقطع صوتي قصير (أقل من دقيقة) في المجلد الحالي. في ويندوز PowerShell اكتب `curl.exe` بدل `curl`.

**(٠) هل الإعداد كامل؟**
```bash
curl -s WORKER/health
```
المتوقَّع: `{"ok":true,"configured":true}`. إن ظهر `"configured":false` فالسطر نفسه يذكر الناقص في `missing` (مثلًا `CAP` أو `GROQ_API_KEY` أو `ALLOWED_ORIGINS`).

**(١) موقع غريب يجب أن يُرفَض:**
```bash
curl -s -X POST WORKER/asr -H "Origin: https://evil.example" -F file=@clip.m4a
```
المتوقَّع: `{"error":"origin"}` (رمز 403).

**(٢) موقعك يجب أن ينجح، والعدّاد ينقص:**
```bash
curl -s -o out.json -D - -X POST WORKER/asr -H "Origin: SITE" -F file=@clip.m4a -F language=ar
```
المتوقَّع: السطر الأول `HTTP/2 200`، وبين الرؤوس `x-athar-remaining: 47`. كرّر الأمر: يجب أن يصير `46`. والملف `out.json` فيه النص المفرَّغ.
- إن ظهر 403: عنوان `SITE` لا يطابق `ALLOWED_ORIGINS` حرفيًّا.
- إن ظهر 502 وفيه `"upstream_status":401`: مفتاح Groq خاطئ؛ أعد الخطوة ٤-د.

**(٣) الاقتباس بالمعنى (فقط إن فعّلته في ٤-ح):**
```bash
curl -s -X POST WORKER/llm -H "Origin: SITE" -H "Content-Type: application/json" -d '{"spoken":"بين النبي أن القوي من يملك نفسه عند الغضب","kind":"hadith"}'
```
المتوقَّع: `{"text":"…"}` فيه نص عربي. إن ظهر `{"error":"llm_disabled"}` فالميزة غير مفعَّلة (وهذا هو الوضع الافتراضي). إن ظهر `{"error":"empty"}` فالنموذج لم يُرجع نصًّا: جرّب نموذجًا آخر في `LLM_MODEL`. (في PowerShell قد تحتاج حفظ الـ JSON في ملف `body.json` واستخدام `-d "@body.json"`.)

### ٤-ز) اربط الموقع بالـ Worker
افتح `public/config.js` وضع عنوان الـ Worker في `asrUrl` وعنوان المستودع في `repo`، ثم ارفع التعديل (Pages يعيد النشر تلقائيًّا). **هذا الملف علني: لا مفاتيح فيه.**
جرّب: ارفع مقطعًا قصيرًا (دقيقة) من الموقع نفسه. إن ظهرت رسالة «غير مصرَّح» فعنوان الموقع غير مطابق لـ `ALLOWED_ORIGINS` (راجع ٤-ج).

### ٤-ح) (اختياري) الاقتباس بالمعنى
في `worker/wrangler.toml` احذف علامة `#` من أول السطرين:
```toml
LLM_PROVIDER = "groq"
LLM_MODEL = "openai/gpt-oss-20b"
```
(أو `LLM_PROVIDER = "gemini"` و`LLM_MODEL = "gemini-2.5-flash"` مع `npx wrangler secret put GEMINI_API_KEY`.) اختر نموذجًا متاحًا في طبقتك المجانية **اليوم** (راجع لوحة المزوّد؛ الأسماء تتغير). ثم `npx wrangler deploy`، ثم الاختبار (٣)، ثم اجعل `llm: true` في `public/config.js`.
**تنبيه صريح:** هذا المسار اختُبر بنماذج وهمية فقط، ولم يُجرَّب بعدُ مع Groq أو Gemini الحقيقيين. جرّبه بالاختبار (٣) وعلى مثال من الموقع قبل الاعتماد عليه.

### ٤-ط) الحدود — وما الذي يحمي حصتك فعلًا
القيم في `worker/wrangler.toml` تحت `[vars]`. لتغييرها عدّل الملف ثم `npx wrangler deploy`.

| المتغيّر | الافتراضي | معناه |
|---|---|---|
| `ALLOWED_ORIGINS` | (يجب أن تضعه) | عناوين المواقع المسموح لها، مفصولة بفاصلة |
| `DAILY_CAP` | `48` | عدد طلبات التفريغ في اليوم لكل الزوار معًا |
| `HOURLY_CAP` | `12` | عدد طلبات التفريغ في الساعة لكل الزوار معًا |
| `IP_DAILY_CAP` | `24` | أقصى ما يأخذه عنوان IP واحد في اليوم |
| `MAX_BYTES` | `25000000` | أقصى حجم للملف في الطلب الواحد (حد Groq المجاني ٢٥ ميجابايت) |
| `ASR_MODEL` | `whisper-large-v3` | نموذج التفريغ (يحدده الـ Worker لا المتصفح) |
| `LLM_PROVIDER` | (فارغ = الميزة مغلقة) | `groq` أو `gemini` |
| `LLM_MODEL` | `openai/gpt-oss-20b` أو `gemini-2.5-flash` | نموذج «الاقتباس بالمعنى» |
| `LLM_DAILY_CAP` | `150` | عدد طلبات «الاقتباس بالمعنى» في اليوم |
| `LLM_IP_DAILY_CAP` | `75` | أقصى ما يأخذه عنوان IP واحد منها في اليوم |

**من أين جاءت الأرقام؟** حصة Groq المجانية لنموذج Whisper هي ٢٨٬٨٠٠ ثانية صوت في اليوم و٧٬٢٠٠ ثانية في الساعة. الموقع يرسل الصوت قطعًا لا تزيد عن ١٠ دقائق (٦٠٠ ثانية):
٢٨٬٨٠٠ ÷ ٦٠٠ = **٤٨ قطعة في اليوم** · ٧٬٢٠٠ ÷ ٦٠٠ = **١٢ قطعة في الساعة**.
يعني: محاضرة طولها ساعتان تستهلك حصة الساعة كلها، والموقع كله يفرّغ نحو ٨ ساعات صوت في اليوم. وإن وصل ملف واحد أطول من ١٠ دقائق حُسب بعدد عشرات الدقائق التي فيه.
وحصة Groq المجانية لنموذج `openai/gpt-oss-20b` نحو ٢٠٠ ألف رمز (token) في اليوم، والطلب الواحد يستهلك نحو ١٠٠٠–١٥٠٠ رمز، فالحد ١٥٠ طلبًا.
(هذه أرقام الحصص وقت كتابة هذا الملف؛ راجع صفحة Rate Limits في لوحة Groq إن تغيّرت.)
عند بلوغ الحد يظهر للزائر أن الحد المجاني انتهى، ويعود العدّاد اليومي عند منتصف الليل بتوقيت UTC (٢ أو ٣ صباحًا بتوقيت القاهرة).

**بصراحة — ما الذي يحميك وما الذي لا يحميك:**
- فحص «الأصل» (`ALLOWED_ORIGINS`) يمنع **المواقع الأخرى** من استخدام خدمتك من متصفحات زوارها. لكنه **لا يمنع البرامج**: أي شخص يستطيع أن يرسل الطلب ببرنامج ويكتب اسم موقعك في الرأس `Origin`.
- لذلك **الحدود (العدّادات) هي الحماية الحقيقية**: مهما فعل أي أحد، لن يمرّ إلى Groq أكثر من الحد اليومي والساعي.
- العدّادات تقريبية: عند وصول طلبات كثيرة في اللحظة نفسها قد يزيد العدد الفعلي قليلًا عن الحد. وGroq نفسه يرفض ما زاد عن حصته.
- **أسوأ ما يمكن أن يحدث — على حدّ علمنا — في الحسابات المجانية التي بلا بطاقة دفع: أن تتوقف الخدمة حتى اليوم التالي، لا أن تصلك فاتورة.** لهذا لا تُضِف بطاقة دفع إلى حساب Groq أو Google المستخدَم هنا، ولا تُرقِّ حساب Cloudflare إلى خطة مدفوعة من أجل هذا المشروع. هذا ما نعرفه اليوم وليس ضمانًا: راجع صفحة الأسعار عند كل مزوّد.
- شخص مُصرّ يستطيع أن يستهلك حدّ اليوم فيتوقف التفريغ عن الباقين حتى الغد. حدّ الـ IP يصعّب ذلك ولا يمنعه. ولصق نص مفرَّغ جاهز في الموقع يعمل دائمًا بلا Worker.
- لتطبيق الحدّ لكل IP يحفظ الـ Worker في المخزن بصمة قصيرة مشفَّرة من عنوان الـ IP (لا العنوان نفسه) تُمحى تلقائيًّا خلال يومين. لا يُحفظ أي صوت ولا نص.
- (اختياري) في آخر `wrangler.toml` إعداد مُعلَّق اسمه `ratelimits` يحدّ عدد الطلبات في الدقيقة لكل IP. لم نتأكد من توفّره في الخطة المجانية؛ الـ Worker يعمل بدونه.

### ٤-ي) إذا تسرّب المفتاح (ظهر في شات، أو ملف، أو صورة شاشة)
1. console.groq.com ← API Keys ← احذف المفتاح القديم (Revoke/Delete) **فورًا**. بعد الحذف يصير بلا قيمة.
2. أنشئ مفتاحًا جديدًا.
3. `cd worker && npx wrangler secret put GROQ_API_KEY` والصق الجديد. لا حاجة إلى إعادة النشر.
4. أعد الاختبار (٢).
(ومثله تمامًا لمفتاح Gemini من Google AI Studio مع `GEMINI_API_KEY`.)

## ٥) Gemini (اختياري، احتياطي فقط)
- لا يدخل في المسار الأساسي. إن استُخدم يوضع مفتاحه كـ Secret في Worker (لا في المتصفح) بالأمر `npx wrangler secret put GEMINI_API_KEY`، ولا نرسل إليه إلا نصوصًا عامة.

## ٦) القياس على تسجيلاتكم (أهم خطوة)
```bash
# ضع التسجيلات في eval/recordings/<اسم المتحدث>/clip_01.m4a ...
read -s GROQ_API_KEY      # الصق المفتاح ثم Enter: لا يظهر على الشاشة ولا يُحفظ في سجلّ الأوامر
export GROQ_API_KEY
node eval/transcribe.mjs
unset GROQ_API_KEY        # امسحه من الطرفية بعد الانتهاء
node eval/real.mjs        # يكتب eval/RESULTS_REAL.md: WER الحقيقي + ما اكتشفه المحرك
```
(في ويندوز استخدم Git Bash أو WSL لهذه الأوامر.)
